## Packet interface and order

1. Finish scoped local UX/compatibility QA and freeze product source. Follow repository policy: push the product change to `main` first, merge it into `Melamedia` preserving QA additions, push that QA candidate, and record a `PUSHED_MAIN_THEN_QA` receipt with both commits, branch and push timestamps. Forward phases check local remote-tracking refs and both main/QA-base ancestry; explicit rollback permits later tracking-ref advancement while retaining historical publication/build/source/preimage bindings; root remains responsible for the actual remote publication evidence. No checkout or Git mutation is performed by these scripts.
2. After review, an explicit `observe` phase hashes the fixed QA public tree twice, checks regular/no-link paths and stable file metadata, and captures public `index.html`/`asset-manifest.json` preimages. It reads no `.env`, credentials, customer rows or backend files. Unknown paths/links/unsupported root directories stop the operation for review. It does not claim backend HEAD, PID or provider state.
3. Compile the **merged QA candidate** with the pinned existing local runtime/dependencies, a separate outside-cloud run/cache and Melamedia public configuration. Bind the full build receipt and source hashes to that exact Git object. Merge the newly emitted entrypoint names into the fresh incumbent index using the existing inverse-exact merger. Root branding/PWA/native/bootstrap bytes are retained, even where generated root assets differ. Filter the publication tar to `static/{js,css,media}/…`, `asset-manifest.json`, `index.html`; the tar must contain exactly the reviewed map. Do not reuse the earlier local integration preview artifact as a QA candidate.
4. Seal a second exact contract: `mainCommit`, `qaCommit`, push proof, QA-branded build receipt, full publication map, archive SHA, exact entrypoint map and fresh observation receipt. Checkpoint requires observation age no more than 30 minutes; subsequent phases compare live bytes to that same preimage rather than assuming freshness. Any protected byte or metadata drift stops.
5. Run, once each, explicit `checkpoint` → `upload` → `publish` → `verify`. Checkpoint creates a private `0700` directory `/root/word-ux-qa-20261026-<releaseBinding prefix>` with `0600` preimages, retention note and journal. Upload validates all archive members, saves the two candidate entrypoints privately and installs immutable static files with atomic no-replace links. Existing conflicting static paths stop. Publish rechecks the entire protected baseline and candidate assets, atomically replaces manifest, then HTML last. Verify rereads candidate and protected files. Existing root-public bytes, modes/owners and old chunks remain exact.
6. Parent performs the authorized synthetic browser/API compatibility check separately. A static byte result is not browser, authentication, signing, OTP or full-product approval. If recovery is necessary, explicitly run `rollback` with the same release binding. It accepts only known old/new entrypoint hashes, restores only private original manifest then index, and retains all old/new chunks, stage, journals and evidence. Failure is not retried blindly; retain partial state and review the journal.

All remote phases take **nonblocking** shared `/run/lock/melamedia-release-maintenance.lock` and exclusive `/run/lock/melamedia-court-owner-import-qa.lock`; the local driver also holds its own nonblocking lock. Busy locks stop instead of queueing another waiter. Mutable writes use immediate hash checks plus atomic filesystem rename under those coordination locks; this is not a native atomic compare-and-swap against unknown writers. SSH is key-only, BatchMode, fixed known host and strict host-key checking. A denial or unknown host stops; no alternate transport, retries or access grant is implemented. No fresh SSH access or approval claim is made by local prep.
