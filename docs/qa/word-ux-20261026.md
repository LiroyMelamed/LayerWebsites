# Existing Word workflow — QA correction

This change separates using a saved Word template from managing its source,
roles and mappings. Persisted case/client actions open the existing authenticated
Word route with display context; returning from signature preparation retains
the document inputs. It reuses platform controls and restores keyboard access to
the shared upload trigger. It adds no future case-stage feature.

The preview request and server authorization remain authoritative. Required
document values, final PDF readiness, explicit review, frozen client/case context,
explicit signer selection and fresh signature geometry are retained. No phone,
OTP, token or credential belongs in source, logs or screenshots.

Local qualification: 75 tests in 10 selected frontend suites passed, including
navigation/return, contextual IDs, use/manage separation, preview invalidation,
Word import and upload keyboard behavior. The full Melamedia-branded local SPA
compiled from product commit `51279a584eceb516209b35cd78339b485f549b01`
with unchanged source and dependencies. Thirteen local static-publisher fixtures
passed. These are not authenticated full-app browser or live API results.

Use the pinned existing frontend runtime/dependencies, with Jest/build caches
outside Documents/Desktop. Exact commands, source hashes, failed and successful
results are in both protected TEST-LEDGER files and the user-task
`outputs/word-ux-fix-20261026` evidence. Read the ledgers before rerunning checks.

The publication target is **Melamedia QA only**, after main-first Git publication
and a merged QA candidate. Follow `ops/word-ux-qa-20261026/README.md`; never use the
generic all-tenant or backend deploy scripts for this frontend task. Preserve
