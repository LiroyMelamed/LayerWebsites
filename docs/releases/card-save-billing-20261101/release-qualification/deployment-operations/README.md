## Why existing wrappers must not be run unchanged

The [backend wrapper](../../../../../scripts/deploy-tenant-backend.sh#L39) updates the live checkout before stopping the old process, unconditionally runs migration backfill and all pending generic migrations, then performs plain PM2 restart/save. It has no drain, explicit effective financial-pause, required maintenance/tenant locking or restricted SQL contract. Backfill can mark every dated migration applied on an empty mature ledger; the migration runner can execute pending DDL/data scripts as PostgreSQL admin. This behavior is unrelated to whether the billing patch itself needs SQL.

The [QA wrapper](../../../../../scripts/deploy-melamedia-qa.sh#L65) omits the backend wrapper's required reviewed SHA and prints an obsolete Idm propagation instruction. The [all-target wrapper](../../../../../scripts/deploy-all-tenants-prod.sh#L70) starts production before QA. Do not remove guards or use a batch wrapper to bypass these failures.

The frontend wrappers rebuild mutable worktrees and mirror with deletion, without an immutable source/artifact or assets-before-HTML publication contract. The [Melamed transport](../../../../../scripts/deploy-tenant-frontend-melamedlaw.sh#L51) additionally disables certificate verification. Both backend/frontend wrappers invoke an external deployment notifier. The restricted release must preserve verified TLS, omit unsolicited notifications, pin source/build/configuration and retain rollback artifacts; it must not use the old transport as a shortcut.

A new restricted **deployment script**, independent of runtime code, can implement: exact active-target allowlist and per-client SHA; existing shared `/run/lock/melamedia-release-maintenance.lock` plus exclusive existing `melamedia-legal-<target>-release.lock`; immutable staging and verified dependencies/artifacts; private configuration preimage; zero SQL by default; identified process stop/start; effective paused environment validation; post-start checks; assets before HTML/manifest; and rollback that preserves payment data. Missing locks, drift or uncertified preconditions must stop it. Do not create locks/access, run `pm2 restart all`, deploy retired Idm, or load the sibling notifier automatically.
