# תוכנית פריסה מדורגת — HOLD, ללא הרשאה לביצוע

העבודה מותרת מקומית ובקריאה בלבד. אין push, פריסה, שינוי שרת/הרשאות/נתוני לקוח, פנייה לספק, חיוב, מסמך או מייל. כל הצעת התאוששות פרטנית קודמת מבוטלת: תקופה שניתנה במתנה נשמרת ללא גבייה, replay או תיקון שדות.

## המקור והמועמדים

main התקדם במהלך הבדיקות מ־`9f01a42d` ל־`4917ca1a3d25e4224bd64fa8c05048285c0741dd`; גם QA התקדם ל־`1d61825c2fac7503f5cf7f25ff3543cde471914d`. התיקון ושער העצירה שולבו בענף מבודד בקומיט `6fab2887d056262cf52ddb773a377e5ad804f0d7`. כל התאמות main נשמרו. אין שינוי בענפים הפעילים או ב־checkout המקביל של המערכת המשפטית.

מזהי המועמדים, תוצאות הבדיקות וגבולות ההוכחה מעודכנים ב־[מטריצת qualification](../release-qualification/README.md). עצי [סימולציית Git הישנה](candidate-simulations.json) ו־[פתרון התרגומים המתוכנן](melamed-planning-tree.json) הם היסטוריים בלבד; הם אינם קומיטי release של השער החדש. קבלות הבדיקות קשורות למקור שבוצע בפועל. תוצאות ממשק ניתנות להעברה בין קומיטים רק עם הוכחת זהות מלאה של קלטי הממשק/הבנייה והתלויות.

כל ענף לקוח מקבל מיזוג נפרד עם היסטוריית הלקוח, qualification והגדרות שלו. נשמרים מיתוג/API/CSP/env/PM2, התאמות אשרף, Word/profile/חתימות, שפות והגנות ה־scope של MelamedLaw ותצורת מור. אין העתקת נתוני משרד, כרטיסים, מחירים, הטבות או סודות בין לקוחות. Idm סגור ומוחרג.

## השער הפיננסי ומה עוד דרוש

`BILLING_OPERATIONS_ENABLED=false` מומש ונבדק מקומית בכל נתיבי הסליקה, המוטציות הפיננסיות, callbacks, הרשמה, חידושים, שדרוגים, הודעות פיננסיות ובגבול התעבורה לספק. snapshot מושהה משתמש רק בנתונים קיימים; callbacks מחזירים 503 עם Retry-After ולא ACK של הצלחה. דגל חסר משמר התנהגות מופעלת, ולכן פריסת הקוד לבדה אינה עצירת גבייה. לא שונתה תצורה חיה. [חוזה, מפת נתיבים וראיות](../billing-pause-gate/README.md).

**השער המקומי אינו מספיק להבטיח אפס השפעות פיננסיות בפריסה.** לפני פריסה ללא סליקה נדרשת תוכנית מאושרת לניקוז כל התהליכים הישנים, הבקשות וה־claims שכבר החלו; טיפול בעמודי תשלום חיצוניים שכבר הונפקו; ושימור/חזרת callbacks ופיוס עסקאות עמומות. אין inbox עמיד חדש, ולא הוכחה מדיניות retry של הספק. אין להפוך pending ל־failed כדי לפתוח חיוב נוסף. גם מסמך/מייל של עסקה שהספק כבר קיבל אינם מתבטלים באמצעות הדגל. אין פעולה חיה עד לסגירת תנאים אלה.

## סכמות, גיבויים ו־rollback

[בדיקת 22:21–22:26 UTC](../release-qualification/readiness/README.md) אימתה קטלוגים ו־grants קיימים בקריאה בלבד בכל ארבעת היעדים: `users.client_profile` עם מגבלת object/8192, טבלת authoring בת 16 שדות עם trigger immutable והרשאות מצומצמות, וטבלאות החיוב הנבחרות. זה אינו מבחן startup/בידוד מלא. RLS כבוי בטבלאות הנבחרות; grants של signup שונים ב־Ashraf/Mor, ולא שונו או הורחבו.

דוחות גיבוי קיימים היו תקינים וטריים, אך הצביעו על generation בן **19.69 שעות**. טענת verified_readback בדוח אינה אימות עצמאי של payload/hash/restore. לא נפתח archive, לא נוצר גיבוי חדש ולא בוצע שחזור. ספירת תיקיות checkpoint אינה מוכיחה לפחות שלוש גרסאות rollback שלמות ולא פעילות בכל רכיב; תנאי זה עדיין HOLD. אין ניקוי או שינוי pin.

לפני פריסה נדרש גיבוי DB עדכני עם גודל/hash/רשימת archive/readback וראיית restore בסביבה מורשית, ושלוש גרסאות חזרה מלאות לכל רכיב. גיבוי R2 שוטף הוא DB בלבד; קוד נשמר ב־Git מאומת, ותצורות/ארטיפקטים פרטיים נשמרים בנפרד. rollback מחזיר מקור/ארטיפקט/תצורה בלבד ומשמר **את כל נתוני התשלומים והתקופות העדכניים**. אין להחזיר DB ישן כדי לבטל קוד: הדבר עלול למחוק settlement או חודש מתנה ולאפשר כפל חיוב.

## חוזה הביצוע וסדר היעדים

הסדר המוצע: **Melamedia QA → AshrafEssa → MorLevi → MelamedLaw**, יעד אחד בכל פעם. QA ראשון מחייב; סדר הלקוחות הוא בחירת סיכון. לכל יעד חוזה משלו: SHA מלא, hashes מקור/manifest/ארטיפקט, תלויות נעולות, PM2/cwd/script/port מזוהים, מיתוג/API/CSP, preimage תצורה פרטי, מצב schema/app-role, גיבוי ו־rollback. drift/נעילה חסרה/יעד לא צפוי עוצרים. אין git pull על מקור משתנה ואין pm2 restart all.

ה־startup וה־wrappers צריכים סקירה/qualification נפרדים עם SHA מחייב ו־SQL/GRANTs מפורטים בלבד; רשימת SQL מאושרת נשארת ריקה. אין להריץ wrappers היסטוריים עם יעדי Idm או migrations/backfill כלליים. נדרשים maintenance shared לכל הפעולה ו־tenant mutex מתאים; אין עקיפת נעילות.

תוצרי compile עם API מדומה הם ראיות QA בלבד, **אסור לפרוס אותם**. בניית פריסה עתידית תהיה חדשה ממקור קפוא עם הגדרות היעד המאומתות. assets לפני HTML/manifest ותוצר חזרה שמור; native/store מחוץ לסקופ.

בדיקות live מותרות כעת: מקור/hash נקי, PM2 מסונן, דגלים לא סודיים, hashes ציבוריים ו־GET אנונימי ל־health; SELECT קטלוג ממוקד בהרשאה קיימת ובטרנזקציה READ ONLY. אין פתיחת SPA/מסך billing או GET מאומת רגיל העלול לנרמל grace, אין payment return/cancel, cron, checkout, ספק או GetDocumentSettings. הקוד המושהה החדש אינו הוכחה שהקוד הישן בשרת הוא read-only.

## חסמים ואישורים שנותרו

- סיום qualification על המועמדים הסופיים; כישלון או דילוג נשארים מתועדים ואינם PASS.
- סביבת הרשמה מלאה ו־fixture PostgreSQL לפרופיל חסרים. אין ליצור גישה/סביבה חדשה במסגרת ההרשאה הנוכחית.
- sandbox שאומת שאינו מסלק כסף אמיתי, סוג מסמך/נמען/משלוח בכל משרד לא הוכחו. CreateDocument קשור לעסקת גבייה; אין להפיק/לשלוח מסמך ניסוי ללא אישור מתאים או לכבות מסמכים כמעקף.
- גיבוי release/restore, שלוש נקודות חזרה, חוזה startup/deploy מצומצם ותוכנית ניקוז/עמודים חיצוניים/callbacks דורשים השלמה מאושרת.
- **Git בלבד:** אישור ל־SHAs/יעדים מדויקים לאחר בדיקת טריגרי CI/אוטומציה; אינו אישור פריסה.
- **קוד/תשתית:** אישור נפרד לחוזי היעדים, גיבוי, תצורה/SQL מפורטים ו־restart מזוהה, לאחר עמידה בתנאי ההשהיה; אינו אישור חיוב/מסמך/מייל או שינוי נתוני לקוח.
- **חיוב עתידי רגיל:** אישור נפרד ליעדים, תחילת הפעלה, מחיר מוסכם, מחזורים תקפים ומסמך/נמען/משלוח שאומתו. אין גבייה רטרואקטיבית, replay של setup ישן או ביטול תקופה שניתנה במתנה. התאוששות פרטנית בוטלה ואינה החלטה פתוחה.
