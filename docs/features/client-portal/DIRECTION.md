# Client portal — approved direction, 13 October 2026

Mode: Operate. Existing-world, source-led implementation of the owner's selected “מה מחכה לי” concept.

Show only confirmed actions ready for the current customer first. Provide visible access to available documents, personal signing history, and the current case status on desktop and mobile.

The owner explicitly superseded the concept shell: preserve the actual desktop sidebar, mobile top toolbar/drawer and native application's existing bottom navigation. Add destinations only; no navbar redesign. Reuse incumbent buttons, popup, segmented switch, inputs, colors and Heebo typography.

Do not change the appearance of case progress. Reuse CaseMenuItem, CaseMenuItemOpen, ProgressBar, CaseTimeline and StageFileUpload without changes. The new query route only selects an authorized case and expands its existing card.

A personal signature is not proof that all parties finished. A returning later-stage signer may appear in both pending and personal history; show the distinction. Never infer signing authority from contact/name matching. Keep current permission, tenant and grant checks. Native signing opens the existing browser-only flow.

Quality bar: exact task states, clear recovery after partial failure, no misleading empty success, no horizontal clipping, readable long names and mixed scripts, complete keyboard popup behavior, comfortable new touch controls, Hebrew/Arabic/English RTL/LTR. Validate changed logic with focused tests and bounded actual-component browser checks. No production or installed-device claims from synthetic fixtures.
